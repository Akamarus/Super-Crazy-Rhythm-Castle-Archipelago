# v0.30.1 — Network security fixes

Client **0.77.1** / APWorld **0.30.0**.

- Remote server addresses now use encrypted WebSockets by default and do not silently retry over plaintext after a TLS failure.
- Incoming decompressed messages are limited to **32 MiB** before parsing; partial messages must finish within **60 seconds**. Idle connections remain supported.
- Connection setup refuses to proceed if the receive protection cannot load.

## Updating

Close the game and replace the client files with the contents of **RhythmCastleAP-v0.77.1.zip**, including license notices.

Your current seed, save and APWorld remain compatible. **scrc.apworld is byte-for-byte unchanged from v0.30.0**; existing players do not need to replace it. Item IDs, progression rules and victory conditions are unchanged.

`localhost:port` still works. If you deliberately use a trusted remote server without TLS, enter `ws://host:port` explicitly; its traffic and room password are unencrypted. Do not use plaintext merely to bypass an unexpected certificate error.

The unpublished cutscene candidate is not included. In-game acceptance and a live very-large-room test have not been performed for this network guard; the automated tests are described in the linked validation record.

See [security validation](../testing/2026-11-08-network-security.md) and [known issues](../KNOWN_ISSUES.md).

## Validation
All 47 release client regression projects, repository validation and 11 tool tests passed. The Release build completed with zero warnings/errors. Targeted tests cover oversized-message rejection, fragmented JSON parsing, fail-closed connection setup, guard reinstallation and TLS failure without plaintext retry.
