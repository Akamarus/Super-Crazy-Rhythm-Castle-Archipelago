In the v0.75.10 capture, samples 9, 13, and 14 have accepted/Rewired input (-0.3110, 0.9504), zero desired velocity, and raw movement intention magnitudes approximately 0.00385, 0.00010, and 0.00010. The contact observer has zero callbacks then. Sample 19 has the same input and desired speed about 6.01. The observer later records actual contacts. Room-running, permission flags, queued action, and restrictor count remain stable. The older capture corroborates low/zero body speed despite accepted input, but lacks motor/contact detail.

Prior native disassembly shows intended motion is input speed multiplied by the supplied delta, before restrictions/acceleration. The motion calculation compares movement against a small threshold and can reset accumulated moving time. Tiny raw intention therefore leaves motor-call delta and speed as leads; it does not prove a restrictor veto. Unity delta recorded by an unrelated 10 Hz observer is not necessarily the delta passed to the motor. Contact callbacks omit triggers, casts, and game-imposed restrictions. Fixed count also cannot exclude replacement or changing internal state.

## Recorder changes

- `MovementCaptureFormatting` records at most 16 restrictors per sample, including total count and an explicit truncation marker. It queries native `GetIl2CppType().FullName`, since the managed wrapper may be an interface/base type. Unity instance IDs are used when exposed; otherwise the native pointer is explicitly labelled `ptr`. Pointer identities are local to a capture, can be reused after destruction, and are not save-stable identifiers.
- Nullable rigidbody-properties IDs use native `HasValue`/`Value`, yielding an integer, `null`, or `unavailable`. A missing/unreadable value is not silently reported as an empty list or a numeric zero.
- Native metadata confirms player-motor `moveSpeed`, `moveSpeedRatio`, `accelerationTime`, and `timeSpendMoving` properties. Property bindings are resolved once when capture begins; readings occur only at the existing sample cadence. Scalar output is culture invariant.
- No retained motor-call delta property was found in the inspected motor metadata. The capture header explicitly labels it unavailable. No hooks, restriction votes, recurring scene scans, or physics/gameplay writes were added.

The existing 12-body, 120-sample limits remain. Identity detail is a sampled observation, so a swap entirely between samples can still be missed. Formatting tests use stand-ins for native wrappers: actual runtime type/nullable acceptance remains a live-game check.
