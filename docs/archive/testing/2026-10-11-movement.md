# Movement diagnostic candidate — October 11, 2026

The cat facing and animal underspeed defect remains unresolved. October 9 captures
showed animals already slow before Hypno Pan, stable physics timing, duplicate dog
names, and a kinematic cat omitted from motor binding. None proves a movement cause.
No physics/gameplay fix or movement-call hook is included.

## Diagnostic changes

- Retain body instance ID with its path in body, component and contact records so
  identically named actors remain distinguishable within a capture.
- Sort player roots, other character roots, other bodies, then detector bodies before
  applying the existing 12-body cap. This is a path-based priority, not role proof.
- Bind motors even when kinematic; prefer player/directable/following wrappers so
  native speed and follow-distance fields are available when exposed.
- Refresh bindings on selected actors every 10 samples (approximately one second).
  Scan the scene only on F8. Facing discovery visits at most 16 actor-local transforms
  per rebind, and property metadata is cached. Capture remains 120 samples at ~10 Hz.
- Read automatic 2D facing cached motion, direction-hold timer, threshold, applied
  facing sign/direction and last enacted look demand time. Report the actual
  childToFlip/childToPointAnyway local scale and forward separately from rootForward.
- Attempt the motor's native identifiable character and cachedState binding to read
  controller behavior, leader references, look demand and motion report. Missing
  properties are explicitly unavailable; nested values use bounded allowlisted reads.
- Preserve prior restrictor runtime identity and nullable property-ID improvements.

## Verification

MovementCapture executable tests failed first for NPC versus detector priority,
player priority and stable actor labels; passed after implementation. Nested motion
report formatting and unknown wrapper tests also failed first and then passed.
`dotnet run --project client/tests/MovementCapture` reports zero failures.
Native interop metadata was read from the local Assembly-CSharp.dll to verify
motor, automatic facing, character state and motion report property names.
Shared full-client build and broader suites are coordinated by the release owner.

## Limits and acceptance

No installation or live capture was performed. Existing captured actor selection
is fixed for the 12-second window: newly spawned actors are not discovered, destroyed
actors are skipped, and more than 12 candidates can still be omitted. A visual
outside the body's first 16 transforms is explicitly unavailable. Rebinding may
miss transitions shorter than approximately one second; snapshots may miss events
between 100-ms samples. Cached state access depends on the actual native wrapper
and may be unavailable. Last enacted look demand does not establish every override.

Supplied motor delta time, per-call requested displacement and call counts are still
unavailable. This observer therefore cannot prove a render/physics command overwrite
hypothesis or establish all restrictions. Contact probes still omit casts/triggers.
A future gameplay capture must show which native components bound and whether the
reported facing values track the visible animal before interpreting them as cause.
No movement repair or gameplay acceptance is claimed.
